# Photobooth server API v1 (handoff for the frontend AI)

Base `http://<server>:5080/api/v1` · JSON · camelCase · times are Unix milliseconds · IDs are 32 lowercase hex chars **generated by the client** (e.g. `crypto.getRandomValues`, 16 bytes -> hex).
The server serves no UI. Clients are the native Windows admin app (localhost) and the Android app. The only web pages are the public download pages `/d/{id}`.

## Auth
Header `Authorization: Bearer <token>`. Roles: **admin** (password) and **device** (paired tablet). Store the token in localStorage; on 401 clear it and re-authenticate.
- `GET /admin/state` -> `{setup}`. If false: `POST /admin/setup {password}` (>=8 chars, once, local only).
- `POST /admin/login {password}` -> `{token}` (admin; lost on server restart). 429 after 8 failures per 5 min per IP.
- `POST /pair/code` (admin) -> `{code}` (6 digits, 5 min). `POST /pair {code,name}` -> `{token,deviceId,serverId}` (device, persistent).

## Tunnel rule
Requests arriving via Cloudflare (`CF-Connecting-IP` header) reach: `/d/*`, `/f/*`, `/frames/*`, `/themes/*` (these two need a device token over the tunnel) and device-authorized `/api/v1/*`. They never reach static files, `/api/v1/admin/*`, `/pair/code`, `/devices`, `/tunnel`, `/qr`, and admin tokens are rejected. Paired tablets work fully over the tunnel; laptop-only functions do not. Large bodies: Cloudflare free caps requests at 100 MB.

## Endpoints
| Method path | Auth | Request -> Response |
|---|---|---|
| GET /health | none | -> `{ok,app,version}` |
| GET /status | any | -> `{ok,now}` |
| GET /devices | admin | -> `[{id,name,created,revoked}]` |
| DELETE /devices/{id} | admin | revokes a device |
| GET /settings | any | -> `{publicUrl}` |
| PUT /settings | admin | `{publicUrl}` (no trailing slash) |
| GET /tunnel | admin | -> `{enabled,hasToken,state,log[]}`; state = `stopped`, `starting`, `online`, or `error: ...` (poll every 3 s) |
| PUT /tunnel | admin | `{token?,enabled?}`; token is write-only |
| GET /events | any | -> `Event[]` (not deleted) |
| PUT /events/{id} | any | `Event` -> the winning `Event` (higher `updated` wins; compare to detect losing) |
| DELETE /events/{id} | any | soft delete |
| POST /events/{id}/frames | any | multipart `f` (PNG), `name`, optional `id` -> `Event`. Idempotent per frame id |
| GET /frames/{eventId}/{frameId} | none locally, device via tunnel | PNG (**no** /api/v1 prefix) |
| GET /sync/pull?since=N | any | -> `{cursor,events,serverTime}` (see ANDROID.md) |
| POST /sync/push | any | `Event[]` -> winning `Event[]` |
| POST /sessions/{id} | any | multipart `eventId`, `photo`, `thumb`, optional `frameId`, files `photo2`..`photo5` (extra framed photos when a guest picks several frames), `gif`, `live` (MP4), `raw1`..`raw9` -> 200. Idempotent; accepts any subset, call repeatedly |
| GET /events/{id}/sessions | any | -> `Session[]` newest first, with `files[]` |
| DELETE /sessions/{id} | any | deletes files |
| POST /sessions/{id}/print | any | `{copies}` (clamped to event.copies) -> 200 |
| GET /prints | any | -> `PrintJob[]` (latest 100) |
| POST /prints/{id}/done or /cancelled | any | updates status |
| GET /qr?text=... | none | -> SVG QR code (local only) |
| POST /events/{id}/theme-image | any | multipart `f` (PNG/JPEG), optional `id` -> `Event` (sets `theme.image`) |
| GET /themes/{eventId}/{imageId} | as frames | image (no /api/v1 prefix) |
| GET /sessions/{id}/files/{name} | any | original file: `photo.jpg`, `thumb.jpg`, `gif.gif`, `live.mp4`, `raw1.jpg`.. |
| GET /events/{id}/export | any | zip of all session files |
| GET /lan | any | -> `{serverId,port,addresses[],publicUrl}` |
| GET /lan/verify?device=&nonce= | none | -> `{serverId,proof}` (see ANDROID.md); proves the server identity on the LAN |
| GET /d/{sessionId} | public | download page (shows "Preparing" until the photo exists) |
| GET /f/{sessionId}/{photo.jpg\|thumb.jpg\|gif.gif}[?dl=1] | public | file; `dl=1` forces download |

## Models
- Event `{id,name,theme{image},frames[Frame],shots=4,countdown=3,retention=10,copies=1,updated,rev,deleted}`. `rev` is server-assigned; never send your own meaning for it.
- Frame `{id,name,slots[Slot]}`; Slot `{x,y,w,h,r}` as fractions 0..1 of the frame image, `r` rotation in degrees about the slot center.
- Session `{id,eventId,frameId,created,ready,deleted,files[]}`; PrintJob `{id,sessionId,eventId,status:queued|done|cancelled,copies,created}`.
- Errors: 400 bad input, 401 auth, 404 missing, 429 rate limited. Plain status codes, no body contract.

Guest flow and kiosk behavior: see ANDROID.md. The Windows admin app (`admin/`, WinForms) is the reference client for events, frames, gallery, print, devices and tunnel.

## Update (v13)
- `POST /sessions/{id}` now answers `{saved:[...]}`: the file field names the server stored. Clients must delete local files only for names listed there.
- `GET /gallery` (any) -> `[{id,name,sessions:[{id,created,frameId,files[]}]}]`: events -> sessions -> files (`photo.jpg`, `photo2.jpg`.., `raw1.jpg`.., `gif.gif`, `live.mp4`, `thumb.jpg`). `db.json` also keeps each session's `files` list.
- `GET /devices` now includes `seen` (ms of the last authenticated request) and `link` (`local` or `internet`, from how the last request arrived). Tablets ping every 10 s, so "offline" = not seen for 45 s.
- `GET /health` returns `version: 4`.

## Update (v14)
- `GET /d/{id}` shows framed photos, GIF, live photo, **original (raw) photos** and a "download everything" zip (`GET /f/{id}/all.zip`). `GET /f/{id}/raw1.jpg`.. are public like the other files (unguessable session id).
- `POST /sessions/{id}` accepts `rawCount` and `photoCount` (expected totals). `GET /health` returns `version: 5`.
- UDP 5081 discovery responder (see ANDROID.md). Installer opens TCP 5080 and UDP 5081 on **private** networks only.

## Update (v23): printing per framed photo
- `GET /sessions/{id}/print-info` (any) -> `{max, used}`: `max` = the event's "copies" setting, now the maximum printed copies for **one photo session** (all framed photos together); `used` = copies already queued (cancelled jobs do not count).
- `POST /sessions/{id}/print` (any) body `{"items":[{"file":"photo.jpg","copies":2},{"file":"photo2.jpg","copies":1}]}`; `file` is a framed photo (`photo.jpg`, `photo2.jpg`..`photo5.jpg`). One print job per item. Answers 200 `{queued,remaining}`, 409 `{error:"limit",remaining,max}` when the total would pass the session limit, 400 for unknown photos. The old body `{"copies":n}` still prints `photo.jpg`.
- `GET /prints` jobs now carry `file`; clients print `/f/{sessionId}/{file}`.

## QR pairing (v8)
No new server endpoint: the Windows admin app calls `POST /pair/code` and `GET /lan`, and shows this text as a QR code:
`photobooth://pair?c=<6-digit code>&a=<lan address>[&a=...]&p=<public url, url-encoded>`
`a` = this laptop's local addresses (`host:port`, tried first, 4 s timeout each), `p` = public address (fallback / saved for later internet use).
The tablet scans it (Android: pairing screen > "Scan QR code"), then calls `POST {address}/api/v1/pair {code,name}` as before. Codes stay single-use and valid for 5 minutes.

- `DELETE /devices/{id}` (admin) now removes the device record (it was: mark revoked). `GET /devices` therefore lists only paired tablets.
- Theme image upload accepts an MP4 (`theme.kind = "video"` is set by the server; `GET /themes/{eid}/{iid}` then returns `video/mp4` with range support).
